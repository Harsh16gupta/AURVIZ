# DeepSeek plus Groq, Meta, and Gemini fallback over OpenAI-compatible REST

Status: amended 2026-11-23 (re-amended) — DeepSeek is the default; Gemini, Groq-hosted Llama, and direct Meta are fallbacks; provider choice is config-only (no picker UI).

DeepSeek (`deepseek-flash` via `https://api.deepseek.com`) is the default. Gemini Flash, Groq-hosted `llama-3.1-8b-instant` (which serves Meta Llama), and direct Meta (`muse-spark-1.3` via `https://api.meta.ai/v1`) are fallbacks. All expose OpenAI-compatible chat-completions with tools, so one OpenAI-shaped HTTP client (OkHttp, no official Kotlin SDK) with baseURL + key + model from BuildConfig/local.properties sits behind the LLMProvider interface. Fallback order is preferred → deepseek → meta → gemini → groq. Fallback triggers on 429/error (never on 401), never carries private mail/memory context to the second provider without a visible "retried on Y" disclosure, and never falls back silently mid-conversation. Room + app work with no cloud key. Language is En+Hi (hi-IN hint). OkHttp gets explicit timeouts (connect 15s, read 60s) with exponential backoff honouring `retry-after`. Failure UX is Retry in timeline + offline queue for memory/schedule writes.
