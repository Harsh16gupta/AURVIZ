# OpenAI-compatible REST client for swappable models

Gemini Pro latency is a risk but Gemini Flash, DeepSeek, and Groq-hosted Llama (Meta models) expose OpenAI-compatible chat-completions with tools. We use one OpenAI-shaped HTTP client (OkHttp/Retrofit, no official Kotlin SDK exists) with baseURL + key + model from BuildConfig/local.properties behind an LLMProvider interface, with in-app picker (Gemini / DeepSeek / Groq-Llama-3.1-8b-instant which serves Meta Llama / optional direct Meta Llama API key) + auto-fallback on 429/error. Default is Gemini Flash free; Groq default model is llama-3.1-8b-instant (llama-3.3-70b is Enterprise-only per research); user holds paid DeepSeek + Meta keys so all are wired from the start but Room + app work with no cloud key. Language is En+Hi (hi-IN hint). First Spec-01 ticket is a live tool-loop spike against the Gemini compat endpoint to verify tool_calls round-trip. Switching providers is a config change, not a code change. Failure UX is Retry in timeline + offline queue for memory/schedule writes.
