# Hand-rolled agent loop, ADK as reference

Status: accepted 2026-11-23.

Google's ADK for Kotlin 1.0 has `requireConfirmation` and Room persistence, but adopting a framework now costs more than it saves two days before the deadline. We hand-roll `AgentLoop` + `ToolRegistry` and copy the patterns, cited in docs: messages list with `role:"tool"` results matched by `tool_call_id`, repeat until a plain answer; max 8 steps with per-step and total timeouts; tool errors return as structured results `{ok:false, error, retryable}` so the model can recover; args validated against the tool schema before execution, unknown tool returns an error result; loop emits `StepStarted`, `ToolRunning`, `NeedsApproval`, `StepDone`, `Failed` into the existing timeline UI. `FakeLlmProvider` becomes scripted multi-turn for tests (multi-step, tool error then recovery, max-step abort, reject path). Prompt-injection defences ship with the loop: email and page text travel only inside tool results, tagged with source and JSON-encoded, and the system prompt states tool content is data, never instructions; memories sit in a delimited system section, never concatenated into the user message.

Consequences: the 13-tool surface (`search_emails`, `read_email`, `send_email`, `open_url`, `get_page_text`, `click`, `scroll`, `extract`, `save_memory`, `search_memory`, `create_schedule`, `list_schedules`, `cancel_schedule`) becomes LLM-visible with schema, risk level, `requiresConfirmation`, and result type each; `runRealPlan`'s single `plan()` call plus createSchedule-only execution is deleted.
